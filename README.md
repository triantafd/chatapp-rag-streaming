# ChatApp RAG (Backend + Frontend + MCP) — with optional streaming

An end-to-end Retrieval-Augmented Generation (RAG) sample that lets you ingest your own PDFs and chat with them. Supports both standard (non‑streaming) replies and Server‑Sent Events (SSE) streaming. The project is split into three apps:

- `backend/` – Node/TypeScript Express API that ingests PDFs, stores embeddings in a local LanceDB vector store, performs semantic search, and calls OpenAI for answers.
- `frontend/` – React TypeScript SPA that calls the backend to ingest data, search, and chat.
- `mcp-server/` – MCP server exposing the backend as tools (search, ask, list, ingest) for Claude Code, Claude Desktop, or any MCP client. See [mcp-server/README.md](mcp-server/README.md).

Each app is an independent npm package (install and run them separately).

## Quick start

```bash
# 1. backend
cd backend
npm install
cp .env.example.openAI .env      # then put your key in API_KEY (or use .env.example.github)
npm run dev                      # http://localhost:4000

# 2. frontend (new terminal)
cd frontend
npm install
npm start                        # http://localhost:3000

# 3. ingest the PDFs once (the vector store is not committed to git)
curl -X POST http://localhost:4000/api/ingest/pdf-directory
#    …or click "Re-index" in the UI
```

## Architecture (high-level)

1) Ingestion
- PDFs are read and converted to per-page text using `pdf-parse` (pagerender).
- Each page is chunked into overlapping segments using LangChain's `RecursiveCharacterTextSplitter` (default: 800 chars, 120 overlap).
- Embeddings (OpenAI `text-embedding-3-small`) are generated for chunks and stored in LanceDB together with metadata (`documentId`, `pageNumber`, `text`).
- Ingestion is incremental: only new or modified PDFs (by file modification time) are embedded, PDFs removed from the folder are dropped from the store, and unchanged PDFs are skipped.

2) Retrieval
- A query is embedded and compared with chunk vectors using LanceDB vector search.
- Optional filter by `documentId`.

3) Generation
- Top‑k chunk texts are concatenated into a context prompt.
- OpenAI/GitHub Models chat model (default: `gpt-4o-mini`) produces a grounded answer.
- The system prompt asks the model to append XML citations per fact using the context’s filename/page.
- Optionally stream tokens over SSE so the UI renders incremental output.

## Backend

### Tech
- Node 18+ / TypeScript
- Express
- LanceDB (local vector DB)
- pdf-parse (pagerender per-page text)
- LangChain text splitter

### Important paths
- Data (PDFs): `backend/src/data/`
- Vector store: `backend/src/lancedb/` — generated by ingestion and git-ignored. After cloning, run ingestion once.
- Postman collection: `backend/ChatApp_Backend.postman_collection.json`

### Environment
Create `backend/.env` from one of the examples:

- OpenAI: `cp .env.example.openAI .env`
- GitHub Models: `cp .env.example.github .env` (uses `BASE_URL=https://models.github.ai/inference` and `openai/...` model names; `API_KEY` is a GitHub token)

All variables:

```
API_KEY=sk-...
# Optional overrides
EMBEDDING_MODEL=text-embedding-3-small
BASE_URL=...
CHAT_MODEL=gpt-4o-mini
PDF_DIR=./src/data
LANCEDB_DIR=./src/lancedb
PORT=4000
```

Notes:
- `PDF_DIR` and `LANCEDB_DIR` default to in-repo paths and are resolved to absolute at runtime.
- Use absolute paths in env to avoid ambiguity.
- The vector store schema expects 1536-dimensional embeddings (`text-embedding-3-small`). If you change the embedding model, reset the store (see below).

### Install & run

```
cd backend
npm install
npm run dev
```

The server starts (default `:4000`). `npm run dev` uses plain `ts-node` without file watching — restart it after changing backend code.

### API overview

- Health
  - `GET /health` → `{ ok: true }`

- Ingest
  - `POST /api/ingest/pdf-directory`
  - Ingests PDFs from `PDF_DIR` (server-side configured). You don’t send a path from the client for security.
  - Returns what changed: `{ ok, dir, added: string[], updated: string[], removed: string[], unchanged: number, chunksEmbedded: number }`

- Documents
  - `GET /api/documents` → `{ documents: string[] }` — PDF files in `PDF_DIR`, whether ingested or not.
  - `GET /api/documents/ingested` → `{ documents: [{ documentId, documentVersion, chunkCount }] }` — what is actually in the vector store (searchable).

- Search
  - `GET /api/search?q=...&documentId=...&max=5`
  - Returns top-k chunks with `documentId`, `pageNumber`, `text` and `score` (distance; lower = closer). Embedding vectors are not included.

- Chat (RAG)
  - `POST /api/chat`
  - Body: `{ messages: Message[], documentId?: string, maxResults?: number }` where `Message = { role: 'user' | 'assistant' | 'system', content: string }`
  - Send the question as the last `user` message. This route uses the tool-choice flow (below), which reads the conversation from `messages[]`; a bare `question` field on its own is not seen by the model.
  - Returns: `{ answer: string, citations: { documentId, pageNumber, text }[] }`
  - The system prompt instructs the model to append XML citations per fact, e.g.:
    - `<citation filename='Solar_Charger.pdf' page_number='6'>short quote</citation>`

- Chat (RAG) — Streaming (SSE)
  - `POST /api/chat/stream`
  - Body: `{ question?: string, messages?: Message[], documentId?: string, maxResults?: number }`
  - Response: `text/event-stream` where each event is `data: { delta?: string, done?: boolean, full?: string, citations?: [...] }`
  - The final event includes `{ done: true, full, citations }`. A single event can arrive split across several network reads, so clients must buffer until the blank line that ends each event (see `frontend/src/services/stream.ts`).

### Tool-choice (function calling) mode

This variant also supports a tool-choice flow where the model decides whether to invoke a `search` tool first:

- When enabled: The model calls `search` only if it believes the user’s question is related to the ingested documents; then it grounds the answer with citations. If unrelated, it answers briefly and emits no citations.
- When disabled: The backend always runs direct RAG before generating.

How to enable/disable:
- Non-streaming route uses direct RAG or tool-choice depending on the code path in `routes/chat.ts` (currently tool-choice).
- Streaming route can use the same logic but streams tokens after the decision. In `routes/chat.ts`, call the streaming helper that wires `AskService.askWithToolChoice(...)` when tool-choice is desired, or use `ask.ask(...)` for direct RAG.

When tool-calling triggers, the backend logs a line similar to:

```
[AskService] Function calling triggered: [ 'search' ]
```

### Ingestion details
- Per-page extraction with `pdf-parse` pagerender (more reliable than splitting on form-feed).
- LangChain splitter: chunkSize 800, overlap 120 (adjust to taste).
- "Re-index" / `POST /api/ingest/pdf-directory` is incremental and does not wipe the store. Running it twice without changes embeds nothing.
- Full reset (e.g. after changing the embedding model or chunking settings):
  - Stop the backend.
  - Delete the vector store folder: `rm -rf backend/src/lancedb`.
  - Start the backend and `POST /api/ingest/pdf-directory` again.

## Frontend

### Tech
- React + TypeScript (Create React App)
- Material UI
- Calls the backend’s endpoints for ingest, search, and chat.
- Optional streaming mode with a UI switch.

### Configure & run

```
cd frontend
npm install
npm start
```

The app calls `http://localhost:4000/api` by default. If your backend runs elsewhere, set `REACT_APP_API_BASE_URL` (read in `frontend/src/services/api.ts`):

```
REACT_APP_API_BASE_URL=http://localhost:5000/api npm start
```

### Typical flow
1) Start backend, then frontend.
2) Ingest PDFs ("Re-index" button, or `POST /api/ingest/pdf-directory`).
3) **Search** shows the raw matching chunks (`GET /api/search`) — useful to check retrieval.
4) **Chat** retrieves chunks and has the model write a grounded answer (`POST /api/chat`), or toggle streaming to use `POST /api/chat/stream`.

### Streaming specifics (frontend)
- Streaming client: `frontend/src/services/stream.ts` (`streamChat(...)`) reads the SSE stream via `fetch` + `ReadableStream`, buffering until each event is complete before parsing it.
- Toggle: The Ask panel includes a “Streaming” switch. When on, the app calls `streamChat`; when off, it calls the regular chat API.
- History window: Only the last 6 messages are sent to the backend to keep prompts compact; you can adjust this as needed.

### Optional: Use Vercel AI SDK to simplify streaming
If you prefer higher-level utilities for streaming and chat state, you can adopt the Vercel AI SDK.

- Install (backend and/or frontend):
  - `npm i ai @ai-sdk/openai`

- Backend idea (Express):
  - Use `streamText` with an `openai(config.chatModel)` model to generate a stream and pipe it as SSE. You would still build your system+history messages and context (as we do), but `streamText` reduces boilerplate when chunking and sending tokens.

- Frontend idea (React):
  - Keep the current `stream.ts` (already works), or try `ai/react` hooks like `useChat` to manage input, messages, and streaming automatically. You may need to align the endpoint response with AI SDK helpers if you choose its built-in handlers.

Note: AI SDK is optional. The included SSE implementation is production‑ready; AI SDK can just reduce code and provide useful abstractions.

## MCP server

Lets Claude Code, Claude Desktop, or any MCP client search and question your PDFs through the backend.

```bash
cd mcp-server
npm install
npm run build
claude mcp add chatapp-rag -- node "$(pwd)/dist/index.js"   # Claude Code; the backend must be running
```

Start a new `claude` session in the project and run `/mcp` — `chatapp-rag` should be connected with 4 tools. Claude Desktop setup, tool details and debugging: [mcp-server/README.md](mcp-server/README.md).

## Testing

There is no automated test suite. Type-check each package with:

```bash
cd backend && npx tsc --noEmit
cd frontend && npx tsc --noEmit
cd mcp-server && npx tsc --noEmit
```

The manual checks below use the two sample PDFs in `backend/src/data/` with the default chunking (800/120). Expected numbers will differ for other PDFs. Run them with the backend running on `:4000`.

### 1. Ingestion is incremental and creates no duplicates

```bash
# start from an empty store
#   (stop the backend) → rm -rf backend/src/lancedb → (start the backend)

# first ingest
curl -s -X POST http://localhost:4000/api/ingest/pdf-directory
#   expect: "added":["Example_Emergency_Survival_Kit.pdf","Solar_Charger.pdf"], "chunksEmbedded":51

curl -s http://localhost:4000/api/documents/ingested
#   expect: Example_Emergency_Survival_Kit.pdf chunkCount 29, Solar_Charger.pdf chunkCount 22

# ingest again without changing anything
curl -s -X POST http://localhost:4000/api/ingest/pdf-directory
#   expect: "unchanged":2, "chunksEmbedded":0 — counts in /documents/ingested stay 29 / 22

# modify one PDF (updating its modification time is enough)
touch backend/src/data/Solar_Charger.pdf
curl -s -X POST http://localhost:4000/api/ingest/pdf-directory
#   expect: "updated":["Solar_Charger.pdf"], "unchanged":1, "chunksEmbedded":22 — still 2 documents, 29 / 22

# add, then remove, a PDF
cp backend/src/data/Solar_Charger.pdf backend/src/data/Copy_Test.pdf
curl -s -X POST http://localhost:4000/api/ingest/pdf-directory
#   expect: "added":["Copy_Test.pdf"], "chunksEmbedded":22 — 3 documents
rm backend/src/data/Copy_Test.pdf
curl -s -X POST http://localhost:4000/api/ingest/pdf-directory
#   expect: "removed":["Copy_Test.pdf"], "chunksEmbedded":0 — back to 2 documents, 29 / 22
```

### 2. Search returns distinct passages

```bash
curl -s "http://localhost:4000/api/search?q=solar%20charger%20specifications&max=5"
```

Expect 5 results from different pages of `Solar_Charger.pdf` (the specifications page, p.9, first) — no passage repeated — and no `vector` field in the results.

### 3. Streaming chat

In the UI, turn **Streaming** on and ask *"Tell me about the specifications of solar charger"*. The answer should stream in and finish without a `JSON.parse` / `Expected ',' or ']'` error. Without the UI:

```bash
curl -N -X POST http://localhost:4000/api/chat/stream \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"What are the solar charger specifications?"}]}'
```

Expect many `data: {"delta":...}` lines, then a final `data: {"done":true,...,"citations":[...]}`.

### 4. MCP server

- **Inspector** (no Claude needed): `cd mcp-server && npm run inspector`, open the printed URL, and call the tools. `list_documents` should show the two PDFs with 29 / 22 chunks.
- **Claude Code**: after `claude mcp add` (above), start a new session and ask *"Which documents are ingested in my RAG app? Then search my PDFs for the solar charger specifications."* Claude should call `list_documents` and `search_documents` and answer with page citations (p.9).
- **Backend down**: stop the backend and call any tool — it should return `Cannot reach the ChatApp backend at http://localhost:4000/api (ECONNREFUSED)…` instead of hanging.
